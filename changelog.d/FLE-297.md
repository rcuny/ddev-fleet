### Security
- **FLE-297: instance isolation, the db container is no longer reachable from other projects.** DDEV attaches every `db` container to the shared `ddev_default` network with the alias `db`, so an instance without its own database (`omit_containers: [db]`) resolved `db` to another project's database and could read and write it with the default credentials. Fleet now writes `.ddev/docker-compose.fleet-isolation.yaml` into every instance: the `db` service keeps only the project's own network, and an instance without a db container gets `db` pinned to `127.0.0.1`. New command `fleet:instance:isolate` lists instances deployed before the fix and, with `--apply`, restarts the running ones.

## Rollout
- ACTION: after the upgrade run `fleet instance:isolate` to list the instances still exposed, then `fleet fleet:instances:isolate --apply` to restart the running ones (ends what runs in their containers; nothing is restarted automatically). New deploys and every restart or redeploy get the override on their own.
- Per-instance random database credentials are not part of this change; the network isolation is the control.
