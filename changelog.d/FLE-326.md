### Security
- **An instance can no longer reach another instance through `ddev-router` on `:8080` and `:8443` by `Host` header (isolation `enforce` mode).** Fleet writes a Traefik file-provider fragment (`fleet-router-access.yaml` in `~/.ddev/traefik/custom-global-config/`) with an HTTP and an HTTPS deny router per instance, bound to the router's HTTP entry points, that lets through only the `ddev_default` gateway (Caddy), the loopback, the instance's own containers and the sources of live links. Fleet pushes the file into the router's own Traefik directory (DDEV copies it there only at a `ddev start`) on every isolation pass and removes it there in `report` and `off`; no router restart, and the port mirror and the router's static configuration are unchanged. The `:443` site mirror is **not** covered yet: the router path stays open on `:443` in `enforce`. `host:isolation:check` verifies the router's copy. See `docs/reference/17-instance-isolation.md`.

## Rollout
- None to apply: the file appears on the next isolation pass of a host in `enforce` mode. Check with an instance's web container: `curl -s -o /dev/null -w '%{http_code}' -H 'Host: <other instance host>' http://ddev-router:8080/` should no longer return the site.
- The isolation pass now logs its warnings (for example the Traefik API down) to the journal.
