### Fixed

- **FLE-188: new deploys failed at `ddev start` on v1.2.0/v1.2.1** (`GIT_SSH_COMMAND` in the instance's `web_environment` contained double quotes and a `$DDEV_APPROOT`, so DDEV generated an invalid `.ddev-docker-compose-base.yaml`). The command now uses the literal container path `/var/www/html/.ddev/fleet_known_hosts`; a regression test checks that no `web_environment` entry holds a quote or a `$`.

## Rollout

- Instances deployed with v1.2.0/v1.2.1 have a broken `.ddev/config.fleet.yaml`. `start` does not re-render the file; only a redeploy (full deploy workflow, new checkout) or a `restart` job (queued by the Claude-token apply action) rewrites it. Redeploy each affected instance, or rewrite its `.ddev/config.fleet.yaml` by hand (`GIT_SSH_COMMAND=ssh -o BatchMode=yes -o StrictHostKeyChecking=yes -o UserKnownHostsFile=/var/www/html/.ddev/fleet_known_hosts`) and run `ddev restart`.
